## 순서 (2026-09-17 확정)

1. **이관 완료** — §1~§15 UI 대조·이관. 현재 위치는 `STATUS.md` 참고.
2. **사이드메뉴 스크롤 / 모달 바깥클릭 버그** — 독립적, 빠르게 처리.
   - 사이드메뉴 펼친 상태에서 배경(회색 처리 영역)이 스크롤되는 문제 →
     펼쳐진 동안은 사이드메뉴 안에서만 스크롤되게. 빈 곳 클릭 시 닫히는
     동작은 유지.
   - 거래처/차량/정비·주유·기타 모달 — 바깥클릭 시 닫혀서 오클릭으로
     입력 내용 날아가는 문제 → 바깥클릭 닫힘 제거 또는 제한 필요.
   - (배포 페이지 모바일 실사용 테스트 중 발견, 2026-09-17)
3. **고급 빌드 최적화** — 이 안에서 먼저 로딩이 느린 원인을 조사하고,
   최적화로 해결이 안 되는 부분이 남으면 그때 로딩 화면 디자인(스피너
   아이콘 또는 원본처럼 로딩 중 배너 이미지 표시)을 추가로 의논.
   - **기본 3종(트랜스파일/트리쉐이킹/압축)은 Vite 기본값으로 이미
     적용 중** — 별도 작업 불필요.
   - **코드 스플리팅도 이미 일부 적용됨**[확인 2026-09-17] —
     `src/app/lazyPages.js`에서 화면 20개가 `React.lazy()`로 분리
     완료, `exceljs`/`html2pdf.js`도 이미 동적 import로 지연 로드 중.
   - **실제 빌드해서 확인한 구체적 문제점**[확인 2026-09-17, `npm run
     build` 실행 결과]:
     1. 메인 번들(`index-*.js`)이 669KB(gzip 196KB)로 큼 — 코드
        스플리팅을 더 세분화할 여지 있음(`build.rollupOptions.output.
        manualChunks` 또는 남은 화면 lazy 전환).
     2. **`public/images/banner_image_Light.png`이 2.26MB**로
        압축 안 된 원본 PNG — 로딩이 느린 원인의 유력 후보. WebP
        변환이나 압축만 해도 대부분 용량 감소 예상.
   - **아직 안 된 것**: 에셋(이미지) 최적화, Brotli 압축, Critical
     CSS 추출. 파일 해싱은 Vite 기본값으로 이미 적용됨.
4. **새 기능 추가** — 아래 "이관 완료 후 진행사항" 목록 (원본에 없던 기존 백로그).
5. **일상점검표(법정 의무) 신규 기능 도입** — 상세 미정. 차량 일상점검이
   법적 의무화되어 추가 필요. 모달 화면 하나만이 아니라 여러 기능 부분이
   같이 바뀌어야 함. 사용자가 피그마로 만든 목업 예시 있음(2026-09-17
   스크린샷 확인 — "8월 30일 일상점검표": 외관점검/상태점검/기타 3개
   섹션, 항목별 양호/불량 토글, 불량상태 조치 기록란, 저장/취소). 착수
   시점에 목업·상세 설명 다시 받아서 착수지시서 작성.

## 이관 완료 후 진행사항 (원본에 없던 새 방향 — 이관 끝난 뒤에만)

- **연동기사 연동해제 시 운행일지 데이터 처리**[정정 2026-09-17 — 예전
  "이중역할(기사+차주)·역할전환 UI" 보류 항목의 진짜 이유는 역할전환
  버튼 UI가 아니라 이 문제였음. "역할전환 UI" 자체는 이관 중 차주/기사
  이중역할 개념을 없애고 연동기사는 차량관리 화면 "+추가"로 등록하는
  방식으로 대체돼서 더 이상 불필요 — 이 항목만 남기고 분리] — 연동
  중엔 그 서브차량이 차주 쪽 사이드메뉴 "[번호] 일지"에서 숨겨지고
  (`subLogMenuItems.js:15-28`, 연동 안 된 sub만 보여줌), 연동 해제되면
  다시 나타난다. 연동 기간에 기사가 입력한 운행일지 기록이 해제 후
  차주에게 어떻게 보이는지가 지금 처리 안 돼 있음. 필요:
  1. 연동해제 시 "기록을 유지할지 리셋할지" 확인 팝업
  2. 연동해제 후에도 차주가 그 차량의 과거(연동 기간) 기록을 조회할 수 있게
- **소속기사 매출화면 정리**(2026-09-17 논의 결론 — 상세 결정 완료,
  착수만 남음)
  - **버그(이관 중 발견, 별도로 근시일 처리 예정)**: "당월 순이익"
    카드 값과 "운송 수입" 카드 맨 아래 "합계" 값이 완전히 같은 값
    (정산액/`settlementTotal`)을 중복 표시. "합계"라는 이름 때문에
    "운송료 - 운임수수료"의 합처럼 보이지만 실제로는 그 계산과 무관한
    별도 값이라 숫자가 안 맞아 보임(예: 운송료 200,000 / 운임수수료
    -0 / 합계 0). 파일: `components/revenue/OwnerMonthlyCards.jsx`,
    `domain/driverSelfRevenue.js`. **착수지시서 작성 전 단계.**
  - **라벨 변경**(위 버그와 같이 처리): 기사 계정 화면 "당월 순이익"
    라벨을 월급제 기사 → "이번 달 월급", 매출제 기사 → "이번 달
    정산액"으로 변경. "순이익" 표현은 차주 계정(실제 매출-지출 계산)
    에만 남김.
  - **토글("전체보기/내몫만보기") — 불필요로 결론, 백로그에서 제거**:
    위 버그+라벨만 고치면 "운송료"(전체)와 "정산액/월급"(내 몫)이
    이미 별도 줄로 나란히 보여서 토글 자체가 필요 없어짐.
  - **배정기간(계약기간) 필터 — 드롭다운 재설계로 해결 방향 확정**:
    근본 원인은 `OwnerRevenueView.jsx`의 "기사" 드롭다운이 "차량 번호"
    기준이라, 같은 차량에 기사가 월 중간에 교체(재계약)돼도 그 달
    데이터가 기간 구분 없이 합산되는 것. 해결 방향: 드롭다운을 "차량"
    기준 → "기사 이름(계약/연동 단위)" 기준으로 개편 — 연동 기사는
    계약(`driverLinks`) 단위로 항목 생성(이름은 연동 시 필수라 이름
    없는 항목 걱정 없음), 미연동 서브차량은 "계약기간" 개념 자체가
    없으므로 지금처럼 차량번호 기준 유지(개편 대상 아님). **착수 시
    별도 착수지시서 필요**(단순 라벨 변경보다 큰 작업 — 드롭다운
    데이터 소스와 워크데이터 필터링 로직 변경 포함).
- **기사 매입 계산서 "공제 전" 선택지 화면에서 삭제** — 결정은 이미
  끝남("공제후"로 확정, `docs/sot.md` §4-5c). 계산 로직은 이미
  `driverInvoiceBasis: 'net'` 하드코딩 완료(`ownerFinance.js:119`),
  `BillingSettingsPage.jsx`의 "공제 전/후" 토글은 선택해도 계산에 반영
  안 되는 죽은 UI로 남아있음. 이관 완료 후 이 토글·"공제 전" 옵션 자체를
  화면에서 제거.
- `driver_direct` 죽은 코드 정리 / 다중 배정 차량 집계(`upsertDriver`가 막아 사실상 닫힘, 참고용).
- 미룸("이관 후 UI 정리"): 테마 저장 위치, 서브차량 설정 배치, 차량관리 라벨, 기사연동관리 UI 패턴.
