### 조사 방법과 보정 결과

- 원본 화면 22개와 모달 13개는 `index.html:184-1494,1613-2376`의 id를 기준으로 삼았다.
- 원본 HTML의 `onclick`·`onchange`·`oninput`·`onsubmit`, JS 템플릿 문자열의 같은 속성, `addEventListener`를 함께 추출했다. 같은 버튼의 열기/닫기처럼 사용자가 하나로 느끼는 동작은 한 행으로 묶었다.
- 추출 범위는 착수지시서의 측정값인 이벤트 핸들러 202개(중복 포함), `addEventListener` 57곳, 원본 JS 10개와 일치하는지 확인한 뒤 124개 사용자 기능 단위로 묶었다.
- React는 함수명이 아니라 화면 문구를 먼저 찾고, `react-app/src/app/AppShellRoutes.jsx:68-105`의 실제 진입 경로와 해당 컴포넌트의 조건 분기를 함께 확인했다.
- 보정 1은 원본 `client-management.js:236-271,338-369`·`index.html:2314-2331`과 React `OwnerScopedClientsView.jsx:43-84,100-145`·`ClientTradeFields.jsx:22-51`을 대조해 **🟡 차이**로 확인했다.
- 보정 2는 원본 `driver-link.js:932-945`와 React `LinkedDriverClientsPage.jsx:56-104,136-178`·`ClientTradeFields.jsx:22-51`을 대조해 **🟡 차이**로 확인했다. 승인된 제외로 돌리지 않았다.

### 판정 읽는 법

- ✅ 동등: 같은 조작·조건·계정 범위가 있다.
- 🟡 차이: 기능은 있으나 위치, 입력 항목, 동작 또는 계정 범위가 다르다.
- ❌ 없음: 대응 조작을 React에서 찾지 못했다. 비고에 확인한 파일과 검색어를 적었다.
- ⚪ 승인된 제외·의도적 변경: 사용자 서면 근거(sot·roadmap 등)가 있거나, 보리가 대화로 확인해 §4에 `[확인: 날짜]`로 기록한 항목이다(최초 조사 때는 서면 근거 3행뿐이었다).
- ❓ 판단 보류: 정적 코드만으로 확정할 수 없는 항목이다.

## 5. 조사하지 못한 것

- 계산 금액의 결과 대조는 착수지시서 범위 밖이라 하지 않았다. 이 문서는 계산 버튼·토글·상세 펼치기 같은 사용자 조작의 존재만 확인한다.
- 순수 색상·간격·글꼴·배치 차이는 기존 UI 대조 완료 범위라 다시 판정하지 않았다.
- 로그인·DB·브라우저 조작은 금지 범위라 실제 계정별 실행은 하지 않았다. 계정 범위는 원본의 `isOwnerAccountType`·`isDriverAccount` 분기와 React의 세션/라우트 조건을 정적으로 대조했다.
- ❓ 판단 보류로 남긴 행은 없다. 정적 코드로 존재 여부를 확정할 수 없는 계산 결과는 애초 조사 범위에서 제외했다.
