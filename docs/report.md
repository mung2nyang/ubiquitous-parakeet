A(react-app `f61a673`)의 공용 부품 `ClearableInput`을 마지막 남은 두 화면에 넣는다. 두 파일 모두 200줄이 넘어 §6 판단을 먼저 받는다.
A~D의 보리 결정 그대로: 여러 줄·날짜·시간·단위(원·km·톤) 칸 제외, 왼쪽 정렬, 누르는 영역 44px, 회색 동그라미 X.
(참고: 다른 작업이 동시에 진행 중 — 커밋 때 이 슬라이스 파일만 골라 담는다.)

### 보리 결정 (2026-10-07, 착수 승인) — 1. A안(나누지 않음) 2. 목록 화살표 숨김 3. 부품이 여백 직접 넣음

(아래는 질문 당시 설명)

1. **200줄 넘는 파일 처리(§6)** — 두 파일 모두 이번 변경은 태그 이름 바꿈 + import 1줄(+1줄)뿐.
   - **A안(AI 추천): 나누지 않음.** 두 파일 모두 이미 "한 화면이라 응집 유지" 이유 주석이 달린 §6 예외 파일(한도 약 250줄)이고, +1줄이라 한도 안.
     `CallDetailForm.jsx` 236 → 237줄(맨 위 주석의 "225줄"이 실제와 달라 숫자를 고침), `CustomerCenterPage.jsx` 227 → 228줄.
   - B안: 이번에 같이 나눔. `CallDetailForm.jsx`의 결제 영역(계산서·부가세 해제·산재보험료·입금 예정일, 184~225줄)을 `CallPaymentPanel.jsx`로 빼서 약 195줄,
     `CustomerCenterPage.jsx`의 문의 작성·내 문의 목록(54~159줄)을 `CustomerInquiryPanels.jsx`로 빼서 약 125줄. 파일 2개가 새로 생기고 범위가 커짐.
2. **운행 상세 입력창 "거래처" 칸의 목록 화살표** — 이 칸은 등록된 거래처 목록에서 고를 수 있는 칸이라, 크롬에서 칸 오른쪽에 ▼ 화살표가 나와 X와 겹친다.
   AI 의견: **X가 붙는 목록 칸은 화살표를 숨긴다**(글자를 치면 목록은 그대로 뜨고, 즐겨찾기 거래처 버튼도 그대로). 기사 초대 창 "할당 차량" 칸은 이미 화살표를 숨기고 있음(`driver-connection.css:138`).
3. **운행 상세 입력창에서 X 밑으로 글자가 들어가는 문제 막기** — 이 창은 자체 CSS(`call-detail-form.css:249`, 칸 여백 지정)가 부품의 "X 보일 때 오른쪽 여백" 규칙과 힘이 같아,
   CSS 불러오는 순서에 따라 여백이 사라질 수 있다. 화면 CSS(311줄, 역시 200줄 초과)를 고치는 대신 **부품이 X를 보일 때 오른쪽 여백을 직접 넣게** 바꾼다(어느 화면 CSS도 덮어쓰지 못함).
   부품(`ClearableInput.jsx`)을 고치는 것이라 A~D 화면에도 똑같이 적용됨 — 보이는 모양은 지금과 같음(지금도 44px).

### 현재 상태 (코드 확인)

| 파일 | 줄 수 | 넣을 칸 | 뺄 칸 (이유) |
|---|---|---|---|
| `day-log/CallDetailForm.jsx` | 236 | 상차지·하차지·플랫폼·거래처·비고 = 5칸 | 운송료(원)·화물 톤수(톤)·계기판(km)·산재보험료(원)·출발/도착 시간·입금 예정일(날짜) |
| `CustomerCenterPage.jsx` | 227 | 문의 제목 1칸 | 문의 내용(여러 줄) |

- 상차지·하차지 칸은 누르면 "어느 칸에 자주 가는 곳을 채울지"를 정하는 처리(`onFocus`)가 있음 — 부품이 `onFocus`를 그대로 넘겨줘서 동작 유지(`ClearableInput.jsx`가 `onFocus` 받아 호출).
- 거래처 칸은 지우면 결제 예정일 자동 계산(`applyClient('')`)도 같이 돈다 — 손으로 다 지운 것과 같음.
- 운행 상세 입력창은 [저장]을 눌러야 저장, 고객센터 문의는 [문의 접수하기]를 눌러야 전송.

### 목표 상태 (기대 동작)

1. 위 6칸에서 A와 똑같이 동작. 상차지·하차지는 X를 눌러도 "자주 가는 곳" 채우기 대상이 그대로 유지.
2. (질문 2) X가 붙는 목록 칸에서는 ▼ 화살표가 안 보임.
3. (질문 3) 어느 화면에서든 X가 보일 때 글자가 X 밑으로 들어가지 않음.
4. "뺄 칸"·저장 방식은 그대로.
