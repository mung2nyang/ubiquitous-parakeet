### 현재 상태

- 마이페이지 [데이터 다운로드] → `DataDownloadModal.jsx`(64줄) → `memberBackup.js`가 비회원 백업과 같은 모양 파일 저장. 일지는 `workLogs`(키: `main`·서브 차량 번호 → 날짜 → 하루 기록). 불러오기 없음(`8f66423` "내보내기만").
- 회원 일지 저장 길: `dayLogCloudCommit.js` `commitMainDayLogMapToCloud` — 여러 날짜를 순서대로 서버에 쓰고, 성공한 날짜만 화면 기록에 반영, 실패하면 거기서 멈추고 "성공 N·실패 M" 안내(이미 있는 기능, 8-B 일괄 미수에서 씀).

- 연동 차량 판정: `domain/driverManagementContext.js:40-44` — 기사 상태가 `disconnected`가 아니고 기사 차량 번호가 같은 차.

### 목표 상태 (이번 슬라이스)

1. 다운로드 확인 창 이름을 "데이터 다운로드 / 불러오기"로, 버튼 줄에 **[파일 불러오기]** 추가(마이페이지 메뉴 위치·대상은 그대로 — 차주·개인 회원만).
2. 파일을 고르면 먼저 **확인 창**: "이 파일의 일지 중 지금 없는 날짜 N일을 더합니다. 이미 있는 날짜는 건드리지 않습니다." [취소][불러오기]. 더할 날이 0이면 "더할 일지가 없습니다" 안내만.
3. 넣는 규칙:
   - 파일의 `main` → 내 메인 차량, 서브 번호 → **번호가 같은 내 차량**. 그런 차량이 없거나 서버에 없는 차량이면 건너뜀(차량을 새로 만들지 않음).
   - **연동 기사가 붙은 차량은 건너뜀**(위 판정과 같은 규칙).
   - 날짜마다: 지금 기록에 **그 날짜가 없을 때만** 더함. 있으면 내용이 달라도 손대지 않음.
   - 모양이 잘못된 파일·하루 기록은 아무것도 안 넣고 "파일 내용이 올바르지 않습니다".
4. 저장은 위 `commitMainDayLogMapToCloud`로 차량별로. 끝나면 "일지 N일을 불러왔습니다(건너뛴 차량 K대)", 중간 실패면 기존 "일부만 저장" 안내 그대로.
5. 서버에서 다 불러오기 전이면 막음(`memberBackupBlockedReason` 재사용).
