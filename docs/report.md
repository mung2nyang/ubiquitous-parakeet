## 뒤로가기 안내 테스트가 가끔 실패하는 문제 — 테스트만 고침 `[x]`

로드맵 밖 보리 요청(2026-10-09, AI가 띄운 작업 제안 → 보리 "조사해").

### 무슨 일이 있었나

- 2026-10-09 문구 정리 2-B 때 `npm test` 전체 실행 중 `src/app/useBackToExit.test.js:57`("설치 앱 홈: 붙잡기 기록 1개 → 뒤로 1번이면 안내…")가 **한 번** 실패: 63줄 `assert.equal(view.idx(), 0)`에서 `1 !== 0`.
- 그 직후 단독 5번·화면 테스트 재실행·이후 CI 전부 통과. 이 파일은 그 작업에서 안 건드림 → 앱 고장이 아니라 **테스트가 가끔 운에 따라 실패**하는 것.

### 원인 조사 (코드 확인 + 실험)

- 테스트는 "뒤로가기 → **20ms 기다리기** → 검사"(`useBackToExit.test.js:44` `wait(20)`)와 "안내 시간 지나기 → **120ms 기다리기**"(`:66`)처럼 **정해진 시간만큼 기다리고** 검사함.
- 테스트용 가짜 브라우저(jsdom 30)는 뒤로가기를 바로 처리하지 않고 **0초 타이머 여러 개를 이어서** 처리함(`node_modules/jsdom/.../SessionHistory.js:19·50·62·136`). 실측: 부하 없을 때도 뒤로가기 신호(popstate)가 **약 6.5ms 뒤**에 옴.
- 전체 테스트(`npm test`)는 여러 테스트 파일을 동시에 돌려 컴퓨터가 바쁨 → 이 이어진 타이머들이 늦어져 **20ms 안에 뒤로가기 처리가 안 끝나면**, 검사 시점에 아직 "뒤로 가기 전" 상태(idx 1)라 `1 !== 0`으로 실패. 실패 모양(63줄, 1 !== 0)과 맞음.
- 확인한 것: ① 안내 타이머(60ms)는 원인이 아님 — 1ms로 줄여도 통과(검사가 타이머보다 먼저 끝남). ② 일부러 부하(바쁜 프로세스 6개)·멈춤을 넣어 재현 시도 → **로컬에선 재현 안 됨**(15회·여러 방식 모두 통과). 그래서 원인은 "정해진 시간 기다리기"가 가장 유력한 후보이고, 100% 증명은 못 함.

### 목표 상태

- 테스트가 **시간을 정해 두고 기다리지 않고, 실제로 그 일이 일어날 때까지** 기다리게 바꿈:
  1. 뒤로가기: `wait(20)` 대신 **뒤로가기 신호(popstate)가 실제로 올 때까지** 기다림(신호 오기 전에 미리 귀 기울여 둠).
  2. 안내 시간 뒤 다시 붙잡기: `wait(120)` 대신 **붙잡기 기록이 다시 쌓일 때까지(idx 1)** 짧게 확인을 반복하며 기다림(최대 2초 — 그 안에 안 되면 실패).
- 검사 내용(안내 1번, 홈 그대로, 안내 시간 안엔 안 쌓음, 지나면 다시 쌓음)은 **그대로**. 약하게 만들지 않음.
- 앱 코드(`useBackToExit.js`)는 **안 건드림** — 앱 동작은 정상.
