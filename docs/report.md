### 현재 상태

- 마이페이지 "데이터 다운로드" 메뉴는 차주·개인 회원만(`MyPage.jsx:102` `canDownload = cloud && !employed`) — 기사 계정엔 [불러오기]도 없음.
- 불러오기(`memberRestore.js`)는 차주 기준: 차량 칸별로 `isOwnUnlinkedCar`(연동 기사가 붙은 차량이면 건너뜀) — 기사 세션에서는 자기 배정 차량이 "연동 차량"이라 전부 건너뜀.
- 기사 세션의 일지는 배정 차량 기록이 `main` 칸에 들어옴(`hydrateEmployedDriver.js` `remapEmployedDriverWorkLogs`), 저장도 `main` → 배정 차량(`mainDayLogRouting.js` `vehicleSupabaseIdForLog`)으로 감. 기사가 손으로 일지 쓸 때와 같은 저장 길(`commitMainDayLogMapToCloud`).
- 실사용자 파일(예전 앱 `plaintext-transport-log` v3): 부산92아5365 72일·운송 131건(7/1~9/30). 빈 옛 칸 4개(`callFares`·`startOdometer`·`endOdometer`·`dailyDistance`)만 빼면 지금 일지 검사(`parsePersistedWorkDataMap`) 통과 확인(AI 실행).
- 운송 건의 거래처는 이름으로 서버 번호를 찾음(`dayLogCloudCommit.js:33` `clientIdByName`). 기사 세션엔 **배정 차량 전용 거래처만** 들어옴(`hydrateEmployedDriver.js` 머리 주석) — 파일의 금오물류(120건)·제일특수(11건)가 그 차량 거래처에 없으면 저장은 되지만 거래처 연결이 빈 채(이름은 원본 칸에 남음).

### 목표 상태 (이번 슬라이스)

1. 기사 계정(연동 중) 마이페이지에 **[불러오기]만** 보임(기사는 다운로드 없음 — 기사 기록은 차주 장부, 기존 결정 유지).
2. 기사 세션에서 불러오기 = **일지만**, 파일의 메인 칸(`workData` 또는 `workLogs.main`) → 배정 차량 일지. 서버에 없는 날짜만 더함(덮어쓰기·삭제 없음, 22-A와 같은 규칙). 주유·정비·기타 칸은 뺌(22-A와 같음).
3. 기사 세션에선 거래처·지출·세금계산서·서브 차량 칸이 파일에 있어도 **건너뜀**(확인 창에 "일지만 불러옵니다" 한 줄).
4. 차주 쪽 불러오기 동작은 그대로(22-A·B 테스트 그대로 통과).
5. 실사용자용 파일: AI가 원본에서 부산92아5365 기록만 뽑아 `{ workData }` 모양으로 만듦(빈 옛 칸 4개 제거, 차주 개인정보·메인 차량·거래처 없음). 코드 아님 — 받는 쪽에 원본 파일을 주지 않기 위함.
