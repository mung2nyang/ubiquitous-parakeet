## 배포까지 순서 5-A — 미연동 서브차량 정비/주유/기타를 그 차량 칸에 저장·불러오기 `[x]`

> 브라우저: 미연동 서브(22가2222) 정비 1원이 서버 서브 칸에만 1행 저장, 새로고침 후 서브 화면에 보이고 메인 화면엔 없음.
> 매출 "차주" 탭에 그 1원이 잡히는 건 5-A 전부터 있던 계산 문제라 **다음 슬라이스 5-A-2로 분리**(사용자 결정, 맨 아래 지시서 확정).

### 1. 목적 (쉬운 말)
차주가 **기사 연동이 안 된 서브차량**에 넣은 정비/주유/기타가 지금은 서버의 메인 차량 칸에 쌓인다.
이걸 그 서브차량 칸에 저장하고, 새로고침해도 차주가 계속 고치고 지울 수 있게 불러온다.
이미 메인 칸에 쌓인 옛 서브 항목은 다음 저장 때 서브차량 칸으로 옮겨진다.

### 2. 현재 → 목표
| | 현재 | 목표 |
|---|---|---|
| 저장 | 모든 항목을 메인 차량 칸에(`syncExpenseRecords.js:51`) | 표시 없는 항목 → 지금과 같은 차량 / **미연동 서브 표시 항목 → 그 서브차량 칸** / 연동 서브 표시 항목·차량을 못 찾는 항목 → 지금처럼 메인 칸(5-B 전까지 유지) |
| 불러오기 | 메인 칸만 차주 목록으로, 서브 칸은 전부 읽기 전용(`hydrate.js:141`·`hydrateOwnerDriverExpenses.js:47`) | 미연동 서브 칸 → **차주 목록(고치기·지우기 가능)** / 연동 서브 칸 → 지금처럼 읽기 전용 |
| 옛 데이터 | 메인 칸에 서브 표시 항목이 섞여 있음 | 저장할 때 서브 칸에 먼저 넣고, 그다음 메인 칸 해당 날짜에서 뺀다. 중간 실패 시 같은 항목이 두 칸에 남을 수 있으나 불러올 때 항목 id로 하나만 남긴다(유실 없음 쪽으로 실패) |

"연동" 판단: 그 차량번호로 `status === 'linked'`인 기사가 있으면 연동(`driverManagementContext.js:73`과 같은 기준). 초대 대기 기사는 미연동으로 본다.

### 3. 건드릴 파일 (react-app)
1. `src/domain/expenseVehicleRouting.js` **(신규, 순수 함수)** — 차량·기사·항목 목록을 받아 "어느 차량 칸에 무엇을 저장할지"를 나눈다. 새 저장소·큐 아님.
2. `src/lib/syncExpenseRecords.js` — 세 함수가 차량을 스스로 고르지 않고 나눠진 대상(차량·항목·운행기록·정리할 날짜)을 받는다. 정리할 날짜(옛 서브 항목이 있던 메인 날짜)는 운행기록·남은 항목이 없어도 비우고 다시 넣는다.
3. `src/lib/expenses.js` — `saveExpenses`가 나눈 대상마다 저장, **서브 먼저·메인 나중**. 서브 운행기록은 `workLogs[ownerKey][차량번호]`.
4. `src/lib/hydrateOwnerDriverExpenses.js` — 서브 칸을 연동/미연동으로 나눠, 미연동은 차주 목록에 합치고(id 중복 제거) 연동만 읽기 전용으로 돌려준다.
5. `src/lib/hydrate.js` — 위 함수 호출 1곳만 바꾼다(기사 목록 전달).
6. 테스트: `src/domain/expenseVehicleRouting.test.js`(신규)·`src/lib/cloudMemorySave.test.js`·`src/lib/hydrate.test.js`.

### 4. 안 건드릴 것 (근거)
- 기사 본인 저장 경로 동작 — 기사 항목엔 차량 표시가 없어 "표시 없는 항목 → 지금과 같은 차량" 규칙에 그대로 걸림(`cloudMemorySave.test.js:173` 소속기사 테스트가 계속 통과해야 함). `hydrateEmployedDriver.js`는 `fetchOwnerDriverExpenses`를 안 씀(`hydrateOwnerDriverExpenses.js:3` 주석·grep 호출부는 `hydrate.js:157` 1곳).
- 화면 파일(`MaintFuelPage.jsx`·`useExpenseForm.js`) — 이미 서브 일지에서 차량번호 표시를 붙여 저장함(`MaintFuelPage.jsx` `openAdd`·`useExpenseForm.js:50`).
- 돈 계산(`financeOwnerExpenseSweep.js`) — 미연동 서브 칸은 지금도 서버에 기사 항목이 없어 읽기 전용 목록이 비어 있음(차주가 메인 칸에만 써 왔음). 옮긴 뒤에도 차주 목록에만 있으므로 합계 이중 계산 없음.
- 서버(DB)·권한 — 변경 없음. 차주가 자기 소유 서브차량 칸에 쓰는 것.

### 5. §8 5대 질문
1. 구독/스냅샷: 화면은 store 구독(`useOwnerExpenses`) — 무변경. 2. 보이는 값: store(= 불러온 서버 값). 3. 쓰기 창구: `saveExpenses` 1곳. 4. 동시편집: 미연동 차량은 차주만 씀 — 충돌 없음(연동은 5-B). 5. 권한: 확인됨(roadmap 5번).

### 6. 기대 동작
- 미연동 서브차량 정비/주유/기타에 항목 추가·수정·삭제 → 서버 그 서브차량 칸에 반영, 메인 칸엔 안 생김.
- 새로고침 후에도 그 서브차량 화면에 보이고 고치고 지울 수 있음. 메인 차량 화면엔 안 보임(지금과 같음).
- 옛 데이터: 아무 항목이나 한 번 저장하면 메인 칸의 옛 서브 항목이 서브 칸으로 옮겨지고, 화면 목록은 그대로(중복·유실 없음).
- 연동 서브차량·메인 차량·기사 본인 화면 동작은 지금과 같음.

### 7. 실패 시 처리
기존 방식 그대로: 서버 저장 실패 → 오류를 던져 "저장하지 못했습니다" 토스트, store는 저장 전 값 유지. **신규 레이어(큐·재시도·임시 저장소) 없음.**
서브 먼저 저장하므로 중간 실패 시 최악은 "두 칸에 같은 항목"이고, 불러올 때 id로 하나만 남긴다.

### 8. §6 200줄
`hydrate.js` 현재 **199줄** — 호출 1곳 교체로 200줄 이하 유지. 넘으면 코드 쓰기를 멈추고 보고.
`syncExpenseRecords.js` 152줄 → 나누는 로직은 신규 파일로 빼서 200줄 이하. `hydrateOwnerDriverExpenses.js` 58줄·`expenses.js` 40줄 여유. 신규 파일 60줄 안팎 예상.
