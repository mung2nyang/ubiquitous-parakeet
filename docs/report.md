# docs/report.md — 현재 슬라이스 착수지시서

## 4-2 산재보험·원천징수 재설계 — 슬라이스 1 "차주 쪽 전체" `[x]` 착수지시서 (react-app `4c3375e`, 2026-09-27 최종 승인)

### 1. 목적 (비개발자용)
차주가 기사차량 설정에서 **기사 유형(4대보험 근로자 / 3.3% 사업소득자)·산재보험 적용·원천징수(3.3%)·필요경비율·산재보험료율**을 정하면, 앱이 **월 단위로 산재보험료와 3.3% 세금을 자동 계산**해
차주 손익(기사 급여 지출)과 기사 관리의 정산 요약 카드에 반영한다. 지금의 "콜 상세 건별 금액을 산재 스위치가 켜졌을 때 기사 정산에서 빼는" 방식은 이 계산에서 더 쓰지 않는다.
서버(DB) 변경 없음 — 차량은 `vehicles.raw`에 통째로 저장되므로(`cloudStorage.js:90` `raw: car`) 새 필드가 그대로 따라간다. 기사 본인 화면·서버 함수는 슬라이스 2.

### 2. 확정 규칙과 계산 (보리 확인 2026-09-27 — 이 값이 테스트의 정답)
- 기준 금액 = **기사 정산액**(매출제: 기사 몫 %/건당 금액 결과, 월급제: 월급). 월보수액 = 정산액 − 정산액 × 필요경비율. 산재보험료 총액 = 월보수액 × 산재요율(기본 1.8%).
- 산재 기사 몫 = 산재 적용 토글 ON이면 총액의 50%, OFF면 0. 차주 몫 = 총액 − 기사 몫. 3.3% = 정산액 × 3.3%(**산재 공제 전 금액 기준**), 원천징수 토글 ON일 때만.
- 기사 실수령 = 정산액 − 산재 기사 몫 − 3.3%. 차주 지출 = 기사 정산액 + 산재 차주 몫(기사 몫 산재와 3.3%는 기사에게서 떼서 대신 내는 돈이라 차주 지출 아님).
- 원 미만 버림(수수료 계산과 같은 방식), 소수 계산 오차로 1원 어긋나지 않게 보정.

| 예시 | 정산액 | 월보수액 | 산재 총액 → 차주·기사 | 3.3% | 기사 실수령 | 차주 지출 |
|---|---|---|---|---|---|---|
| 매출제 20%, 운송료 1,000,000, 사업소득자(둘 다 ON) | 200,000 | 139,000 | 2,502 → 1,251·1,251 | 6,600 | **192,149** | **201,251** |
| 월급제 2,000,000, 사업소득자(둘 다 ON) | 2,000,000 | 1,390,000 | 25,020 → 12,510·12,510 | 66,000 | **1,921,490** | **2,012,510** |
| 월급제 2,000,000, 4대보험 근로자(둘 다 OFF) | 2,000,000 | 1,390,000 | 25,020 → 25,020·0 | 0 | **2,000,000** | **2,025,020** |

**기본 방침 (승인 시 이대로 구현 — 다르면 말씀):** ① 산재보험료 총액은 모든 기사차량에 기본 계산한다(적용 제외는 요율을 0으로). ② 근로자도 같은 식을 쓴다(정확한 근로자 요율이 다르면 요율 칸을 고쳐 대응).
③ 기존 차량의 새 필드 미설정값은 "기존 동작 유지"(원천징수 OFF, 유형 = 사업소득자)이고, **새 차량 폼에서만** 유형별 기본값(사업소득자: 두 토글 ON, 근로자: 둘 다 OFF)을 자동 채운다. ④ 필요경비율 기본 30.5%, 품목·차종 선택으로 43.1% 채움 가능(로드맵 표, 저장은 숫자만). 요율·경비율은 **차량별**로 저장(차주 전체 설정으로 옮기는 건 후속).

### 6. AGENTS §8 5대 질문
1. 화면은 `useOwner*` 구독, 카드는 기존 `load` 없이 같은 계산 함수 결과. 2. 값 출처: 차량 폼 draft → Store(cars) → localStorage·Supabase(`vehicles.raw`). 3. 쓰기 창구는 기존 차량 저장 경로(`upsertCar` → 기존 요청 함수)를 그대로 — 우회 없음.
4. hydrate·동시편집 경합: 새 필드도 기존 차량 병합 규칙을 따름(서버가 정본). 5. 권한: 차주만 편집(기사는 읽기 — 슬라이스 2). 새 권한 결정 없음.

### 7. 검증
- `npm test`(unit + 화면)·`npm run typecheck` 0에러·strict-inventory 진단 수 불증가(기준선 428). 계산은 §2 표를 정답으로 하는 직접 값 검사.
- **테스트 진실성**(플레이북 §6): 계산 한 줄(예: 요율·50% 몫)을 바꾸면 새 테스트가 FAIL하는지 CLI 원문으로 확인 후 원복. **저장 왕복**(플레이북 §1·§7): 새 필드가 저장→새로고침 복원에서 유지되는지 테스트, 잘못된 타입은 거부.
- 플레이북 트리거(`store/**`·`lib/hydrate*`·`domain/finance*`) 해당 — 위 검증으로 대응.
- **브라우저 검증(보리, 차주 계정):** 기사차량 만들기/수정 → 유형·토글·경비율(품목 선택)·요율 입력 → 새로고침 후 유지 → 그 차량에 운행 입력(운송료 1,000,000·20% 또는 월급제 2,000,000) → 매출 손익의 기사 급여 지출과 기사 관리 정산 요약이 §2 표와 같은지.
