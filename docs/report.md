# docs/report.md — 현재 슬라이스 착수지시서

## 로드맵 18-A — 화면 전환 움직임 `[x]`

보리 지시(2026-10-08): 화면 넘길 때 앱처럼 움직임 넣기, 착수지시서로 진행.

### 시작 전 상태

- 오늘 "바로 수정"한 화면 다듬기는 react-app `4e1e456`로 먼저 커밋(보리 지시, push 전). 이번 슬라이스는 그 위에서 시작.

### 현재 상태 (코드 확인)

- 화면 이동 시 움직임 없음: 화면 전환 코드 없음(`@keyframes`는 로딩 점·스피너 2곳뿐, `grep`). 팝업(`.modal-overlay`, `account-flow.css:494`)도 바로 나타남(애니메이션 규칙 0건, 브라우저 확인).
- 화면들은 `AppShell.jsx`의 `<AppShellRoutes>` 한 곳 안에서 바뀜. 하단 메뉴·사이드 메뉴·알림 패널은 그 바깥이라 안 움직여도 됨.
- 이동 종류는 라우터가 알려줌(`useNavigationType` — 이미 `useBackToExit.js:37`에서 사용): 새 화면(PUSH)·뒤로(POP)·교체(REPLACE).

### 목표 상태 (기대 동작)

1. **안쪽 화면으로 들어갈 때**(예: 마이페이지 → 공지사항, 달력 → 일지): 새 화면이 오른쪽에서 살짝(약 24px) 밀려 들어오며 나타남, 약 0.2초.
2. **뒤로 갈 때**(헤더 뒤로 버튼·휴대폰 뒤로 버튼 모두): 왼쪽에서 살짝 들어옴.
3. **하단 탭끼리 이동**(홈·일일운행·매출·마이페이지): 밀림 없이 짧게(약 0.15초) 서서히 나타남.
4. **팝업**: 배경은 서서히, 팝업 상자는 아래에서 살짝 올라오며 나타남(약 0.18초).
5. 움직이지 않는 경우: 처음 앱을 열 때, 주소는 같고 보던 달(`?y=&m=`)만 바뀔 때, 17번 "한 번 더 누르면 종료"의 붙잡기 기록(같은 홈 주소)일 때.
6. 휴대폰 "동작 줄이기" 설정이면 움직임 전부 없음.
- 나가는 화면은 따로 움직이지 않음(들어오는 화면만). 화면을 새로 만들지 않고 겉 상자에 효과만 다시 걸어서, 작성 중이던 일지 등의 상태·저장 흐름은 그대로.

### 안 건드릴 것

- 저장 안전 확인(`confirmLeaveIfUnsafe`)·`useBackToExit.js`·각 화면 파일 — 그대로. 화면 이동 방식은 안 바꾸고 보이는 효과만 붙임.
- `account-flow.css`(571줄, 200줄 초과) — 팝업 효과는 여기 말고 `app-shell-base.css`에 둠.
- 팝업 공용 클래스(`.modal-overlay`·`.modal-content`, 13곳 사용)는 **위치·크기 속성은 안 바꾸고** 나타나는 효과만 추가(§5-6 해당 없음, 13곳 모두 같은 효과).

### 주의 (확인한 위험)

- 화면이 밀려 들어오는 0.2초 동안은 그 안의 "화면 고정" 요소가 겉 상자 기준으로 잡힘. 화면 고정 요소(팝업·날짜 선택 등)는 모두 사용자가 연 뒤에 뜨는 것이라
  들어오는 0.2초와 안 겹침(`position: fixed` 파일 9개 확인, 하단 메뉴·사이드 메뉴·알림 패널은 겉 상자 바깥). 효과가 끝나면 겉 상자 변형은 사라짐.
- 겉 상자를 직접 자식으로 지정하는 규칙 없음(`.main-app-container >` 0건, `grep`).

### 실패 시 처리 — **신규 레이어 없음**
