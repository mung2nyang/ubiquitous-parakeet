> 재구성) 착수 전 조사·대화 결과. §16 전체는 A(이번)/B(설정화면 뼈대)/

### 현재 상태
`LinkedDriverManagementPage.jsx`(연동기사/미연동 서브차량 공용 관리 화면)의
미연동(unlinked) 모드 프로필 카드에 두 가지 문제가 있다:
1. 원본은 서브차량 로그 진입 버튼 옆에 톱니바퀴(빠른 설정) 버튼이 나란히
   있었는데(`script.js:1313-1322` `gearBtn`), react-app엔 이 버튼 자체가
   없다. 지금은 "운행일지" 칩 하나만 있다(`LinkedDriverManagementPage.jsx:133-140`).
2. 미연동 서브차량은 등록 시 기사 이름(`driverName`)·전화번호(`driverPhone`)를
   입력받아 저장하는데(`domain/cars.js:86-87`), 프로필 카드는 이 값을 전혀
   안 쓰고 차량번호만 보여준다(`nameLine`/`initial`이 `unlinked`이면 무조건
   `plate`만 씀 — `LinkedDriverManagementPage.jsx:118-119`, 전화번호 줄도
   `!unlinked`일 때만 렌더 — 129행). 연동기사는 이름·차량번호·전화번호가
   다 보이는 것과 비대칭. 화면 맨 위 제목은 이미 `ctx.car?.driverName`을
   정상적으로 쓰고 있어서(101-102행) 제목엔 이름이 나오는데 카드엔 안 나오는
   상태(보리 스크린샷 지적, 2026-09-18).

### 목표 상태
1. **톱니바퀴 버튼 추가** — "운행일지" 칩을 왼쪽으로, 오른쪽에 톱니바퀴
   아이콘 버튼(신규)을 나란히 배치(보리 스케치 확인, 2026-09-18). 아이콘은
   새로 그리지 않고 이미 앱에 있는 톱니바퀴 SVG(`SideMenu.jsx:39-46`
   `GearIcon`, 원본 `script.js:1317`의 path와 문자 단위로 동일 확인됨)를
   로컬 컴포넌트로 재사용. 버튼 스타일은 기존 공용 아이콘 버튼 클래스
   `action-icon-btn`(`side-menu.css:183`, 순수 아이콘 전용 버튼이라 §9/§12
   때 있었던 "텍스트에 오용" 문제와 무관) 재사용, 새 CSS 규칙 추가 없이.
   **클릭 시 동작**: §16 슬라이스 B(설정화면)가 아직 없으므로, 이번
   슬라이스에서는 임시로 `showToast?.(SOON)`("준비 중입니다.") 처리 —
   같은 파일에서 "운송내역서" 칩이 최근까지 쓰던 것과 동일한 임시 패턴
   (이번 승인 대상에 이 가정 포함, 이견 있으면 착수 전 알려달라).
2. **프로필 카드 이름/전화번호 표시** — 미연동 모드에서 `ctx.car?.driverName`이
   있으면 연동기사와 같은 형식(`{이름} · {차량번호}`)으로, 없으면 지금처럼
   차량번호만. 전화번호는 **이름이 있을 때만** `<small>{driverPhone || '연락처 없음'}</small>`
   표시(이름 없는 차량은 "기사"가 특정 안 된 상태라 전화번호 줄 자체를 안 보여줌
   — 이 판단 기준에 이견 있으면 착수 전 알려달라).

### 건드릴 파일 (예상 2개)
1. `react-app/src/components/drivers/LinkedDriverManagementPage.jsx` —
   로컬 `GearIcon`(한 줄 SVG로 압축, 줄 수 절약) 추가, 프로필 카드 우측
   버튼 영역을 "운행일지" 칩 + 톱니바퀴 버튼 나란히 배치로 변경,
   `nameLine`/`initial`/전화번호 로직에 `ctx.car?.driverName`/`driverPhone`
   반영.
2. `react-app/src/components/drivers/linked-driver.css` — 위 두 버튼을
   가로로 나란히 배치하기 위한 **새 래퍼 클래스 1개**만 추가(기존
   `.linked-driver-profile-card > div:last-child`의 `flex-direction: column`
   규칙은 연동 모드 쪽(차량번호+상태뱃지 세로 쌓기)이 계속 써야 해서
   안 건드림 — 새 클래스로 그 안에서만 가로 배치).

### 안 건드릴 것
- `action-icon-btn`(`side-menu.css:183`) 자체 규칙 — 그대로 재사용만, 수정
  없음(다른 화면 다수 공유 클래스라 §6 체크리스트 6항 대상이지만, 속성
  변경이 아니라 순수 재사용이라 영향 없음).
- 연동(linked) 모드 쪽 프로필 카드 분기 — 지금 그대로.
- §16 슬라이스 B(설정화면 라우팅)·C(차량별 설정값) — 이번엔 톱니바퀴를
  누르면 토스트만 뜨고, 실제 설정화면 연결은 다음 슬라이스.

### §6 200줄 체크
`LinkedDriverManagementPage.jsx` 현재 177줄. 이번 변경(아이콘 컴포넌트+버튼
마크업+이름/전화번호 로직)으로 대략 +20줄 예상 → 200줄 턱걸이 가능성 있음.
넘으면 별도 분리설계 없이 SVG를 최대한 압축(원본처럼 한 줄)해서 200줄 안에
맞춘다. 그래도 넘으면 코드 리뷰 때 별도 보고.

### 실패 시 처리
새 저장/복구 레이어 없음. 기존 `useOwnerCars` 구독으로 이미 로드된
`car.driverName`/`car.driverPhone`을 화면에 표시만 하는 읽기 전용 변경,
되돌릴 새 상태 없음.
