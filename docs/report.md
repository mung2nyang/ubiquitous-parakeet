### 경위

1차 조사에서 발견한 구조 차이(`docs/archive/audit.md` "1. 홈(메인
캘린더)" 참고): 원본은 홈 캘린더·리포트의 "월간 운송료 정산" 위젯을
거래처별로 나눠 보여주고(거래처별 운송료 + 정비비·주유비·통행료 등 지출
3종까지 같이 표시), react-app은 입력 방식(고정노선 횟수×단가 vs 콜상세
직접 입력)별로 나눠 보여준다(지출 3종 요약은 이 카드에서 아예 빠져 있음).

보리가 위치("캘린더카드 하단의 정산카드" 맞음, `CalendarMonthSummary.jsx`)
확인 후 "원본대로 수정해" 지시 → 감시관이 착수 전 조사 진행.

### 조사 내용 (착수지시서 작성 전 반드시 참고)

**원본 계산 로직이 예상보다 크다** — `updateSummary`(`script.js:3529-3634`)
와 그 호출부(캘린더 렌더링 함수의 일별 누적 루프, `script.js:3330~3420`
부근)가 실제로 계산하는 것:
- 고정노선 운송료 — 연동된 거래처가 있으면 그 거래처 매출로, 없으면
  "고정 기본 운송료" 버킷으로.
- 콜상세 운송료 — 등록 거래처면 그 거래처 매출로, 아니면 "미지정 거래처
  운송료" 버킷으로.
- 거래처별 수수료 — **저장 시점 스냅샷 우선**(`commissionSnapshot`), 없으면
  현재 거래처 설정으로 폴백. percent/고정액 두 방식.
- 파렛트 회수 청구액(고정노선+파렛트 옵션 켜진 경우만).
- 기사차량(서브 로그) 수수료 — `activeLogId !== 'main'`일 때만, 정률/건당
  두 방식.
- 실 운행거리(옵션 켜진 계정만).
- 부가세 = `(운송료합+파렛트) × 10%`, 합계 = 운송료+파렛트-수수료-기사수수료+부가세.
- 정비비/주유비/통행료(미수) 3종 별도 행.

**중요한 추가 발견 — 홈 캘린더와 리포트가 같은 계산을 공유**:
react-app의 `domain/day-record.js`의 `monthWorkFareSummary`(단순 버전 —
거래처별 분류·수수료·파렛트·기사수수료·거리 전부 없음)를 **홈 캘린더
(`CalendarPage.jsx`)와 리포트 요약 화면(`lib/report.js`의 `buildMonthReport`)
둘 다 그대로 쓰고 있다.** 즉 캘린더만 원본 구조로 고치면, 이제 리포트
요약 화면과 캘린더가 서로 다른 방식으로 표시되는 새로운 불일치가 생긴다
(둘 다 원래는 같은 문제를 안고 있었음 — 1차 조사 §1·§9 둘 다 같은 항목으로
지적됐던 것과 일치).

**좋은 소식 — 거래처별 분류 로직은 이미 부분적으로 존재**: `lib/report.js`의
`buildDetailReport`(세부 내역서 화면용, `getCallDetailCommissionAmount`
재사용)가 이미 "거래처별 매출·수수료 스냅샷 우선" 로직을 구현해뒀다 —
콜상세 부분은 이걸 재사용/일반화하면 될 것 같다. 다만 고정노선 거래처
연동·파렛트·기사차량 수수료·실운행거리는 `buildDetailReport`에도 없어서
새로 포팅해야 한다.
