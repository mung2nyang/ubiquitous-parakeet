### 1. 목적 (쉬운 말)
연동 해제 때 기사 계정으로 복사된 기록 중 **고정노선 금액**이 0원으로 보일 수 있는 문제(②)와 **노선별 칩 횟수**가 안 보이는 문제(①)를 고친다(로드맵 7번 `[확인: 2026-10-01 보리]`).
해제 순간 서버가 그 차량의 고정노선 거래처(1회 단가)와 노선 이름표도 함께 기사 계정에 넣는다.

### 2. 조사 — 지금 상태 (근거)
- 고정노선 금액 = 그날 횟수 × **고정노선 거래처의 1회 단가**(`financeCore.js:105-128`). 거래처 고르는 규칙: 그 차량 전용(`scopedToVehicleNumber` = 차량 번호) 고정노선 거래처 → 없으면 계정 공용 고정노선 거래처(`clients.js:23-31`). 계정당 고정노선 거래처는 1곳만(`clients.js:137`).
- 7-D-1 복사(`0012` `copy_driver_link_records_internal`)는 **콜에 쓰인 거래처만** 복사 → 고정노선 거래처는 콜에 안 나오면 빠짐.
- 노선 칩: 그날 기록 `fixedRouteCounts`는 **노선 이름표 id**별 횟수, 이름표(상차지→하차지)는 계정 설정 `fixedRoutePresets`(`profiles.settings`)에 있고 칩은 설정 `fixedRouteOn`이 켜져야 보임(`DayLogPage.jsx:74`). 7-D-1은 설정을 복사 안 함.
- 서버 실제 데이터(읽기 전용 조회, 2026-10-01): 노선 칩 횟수가 있는 기록 **0건**, 모든 계정 `fixedRouteOn` 꺼짐·이름표 0개, 고정노선 거래처 **5곳**(차주 a0b9fa70: 11가1111 전용 "기사고정노선"·공용 "고성노선(지우지말것)"·22가2222 전용, 그 외 2곳 — 처음 조회 때 결과 표가 일부만 보여 "1곳"으로 잘못 적었다가 재조회로 정정).
  고정 횟수가 있는 기록은 있음(예: 11가1111 1건, 울산81사3906 55건). → 지금 시험 데이터 영향은 작지만 실제 사용자용으로 필요.

### 11. 확인 요청
1. 고정노선 거래처 고르는 규칙 = **앱과 같게**(그 차량 전용 → 없으면 차주 공용)로 할지 — 추천.
2. **기사 계정에 이미 다른 고정노선 거래처가 있을 때** — 앱은 계정당 고정노선 거래처 1곳만 씀(모든 날에 같은 단가). 추천: **기사 것을 그대로 두고, 복사한 거래처는 일반 거래처로만 넣음**
   (그 경우 복사된 날 고정노선 금액은 기사 쪽 단가로 계산됨 — 알려진 한계로 기록). 다른 방법: 복사한 것을 고정노선으로 바꾸고 기사 것은 끔(기사의 현재 금액이 바뀜).
3. **노선 칩 표시 켜기** — 추천: 이름표를 1개라도 추가했고 기사 설정에 칩이 꺼져 있으면 **켬**(안 켜면 ①이 해결 안 됨). 다른 방법: 이름표만 넣고 켜기는 기사에게 맡김.
