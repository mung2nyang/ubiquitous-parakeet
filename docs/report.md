## 로드맵 33 — 업데이트 뒤 켜 둔 앱에서 화면 먹통 막기 `[x]`

로드맵 "출시 전 순서 개편" 1단계 ③(배포 안전). 보리 휴대폰 매출 화면 먹통 제보(2026-10-09) → "CSS만 고쳐도 먹통"(보리).

### 현재 상태 (코드·배포 확인)

- 화면 17개는 처음 누를 때 따로 받음(`app/lazyPages.js` `lazy(() => import(...))`). 화면마다 JS 파일과 CSS 파일이 따로 있음.
- 배포할 때마다 바뀐 화면의 파일 이름(뒤의 해시)이 바뀌고 옛 파일은 지워짐. **CSS만 고쳐도 그 CSS 파일 이름이 바뀜** → 보리 말대로 CSS 수정만으로도 생김. 실측: 예전 `RevenuePage-CuOLPRup.js` → 지금 404.
- 업데이트 전에 켜 둔 앱은 옛 이름으로 요청 → 404 → 화면 받기 실패. 이때 대신 보여 줄 장치(오류 경계)가 앱 어디에도 없어서(`grep ErrorBoundary` 0건) 앱 전체가 사라짐 = 먹통.
- Vite는 화면 받기가 실패하면 `vite:preloadError` 신호를 보냄(배포 파일에서 확인 — JS·CSS 둘 다, 받기 실패 때). 지금은 아무도 이 신호를 안 들음.
- 주소 문서(`index.html`)는 10분 보관(`Cache-Control: max-age=600`)이지만 새로고침하면 서버에 새 판인지 다시 물어봄 → 새로고침 한 번이면 새 파일 이름을 받음.

### 목표 상태 (기대 동작)

1. **업데이트 뒤 켜 둔 앱에서 새 화면을 누르면 → 앱이 저절로 한 번 새로고침**해 새 파일을 받고 그 화면이 열림(사용자는 잠깐 깜빡이는 정도).
2. **새로고침 뒤에도 또 실패하면(10초 안 두 번째)** 다시 새로고침하지 않고(무한 반복 방지) 먹통 대신 안내:
   - **화면을 불러오지 못했습니다.** / **잠시 후 다시 시도해 주세요.** + [다시 시도] — 32번 막기 화면과 같은 말투·모양(`boot-retry.css` 재사용). 하단 메뉴는 그대로 보여 다른 화면으로 갈 수 있음.
3. 평소(업데이트 없을 때)엔 아무 변화 없음.

### 실패 시 처리 — **신규 장치 2개(이번 항목 자체) — 보리 승인 대상(AGENTS §7)**

- ① 받기 실패 때 1회 자동 새로고침(10초 안 재시도 금지) ② 화면 오류 때 안내 화면. 저장 쪽 장치 아님 — 새 저장소·큐 없음. 쓰는 기록은 `sessionStorage` 시각 1개(새로고침 반복 막기용, 탭 닫으면 사라짐).
- 자동 새로고침 때 **쓰던 일지가 날아갈 걱정**: 일지 입력은 즉시 저장(자동 저장)이고, 저장이 안 끝난 상태면 기존 "나가기 확인"(`durableWriteGuard`)이 그대로 동작. 화면 받기 실패는 **다른 화면으로 넘어가려 누른 순간**에만 생겨서 입력 중 갑자기 새로고침될 일은 없음.
