# docs/report.md — 현재 슬라이스 착수지시서

## 로드맵 20-A — 일지 수정·추가 칸이 열리면 그 자리로 내려가기 `[x]`

보리 지시(2026-10-08): 일지에서 "수정"을 눌러도 아래 입력 칸이 열렸는지 모름 → 자동으로 내려가서 보이게, 바뀐 것도 알 수 있게.
20-B(수정 중인 카드에 테두리 표시)는 다음 슬라이스 → 보리 지시로 제외(2026-10-08).

### 현재 상태 (코드 확인)

- 입력 칸(`InlineSheet.jsx`)은 0.4초 동안 펼쳐지고 끝 무렵 내용이 서서히 나타남(`day-log.css:2-24`). 닫을 때도 접힘 → **애니메이션은 있음**.
- 그런데 운행 일지 입력 칸은 카드 목록 → 합계 상자 → "+ 운행 일지 추가" **아래**(`CallDetailList.jsx:44-76`), 정비·주유·기타 칸도 목록·추가 버튼 아래(`DayLogExpenses.jsx:37-55`)에서 열림 → 보통 **화면 밖에서 펼쳐져** 눌러도 반응이 없는 것처럼 보임.
- 이미 열린 칸에서 다른 항목 "수정"을 누르면 칸은 그대로고 내용만 순간 교체(운행 일지는 `key={editingCallId ?? 'new'}`로 새로 그림 `DayLogPage.jsx:189`, 정비·주유·기타는 같은 칸에 값만 바뀜).
- **기존 결정과 충돌**: `docs/sot.md` 4-9(2026-08-31) "일지 인라인 시트 … `scrollIntoView` 없음", 테스트 `inlineSheetCss.test.js:35-38`이 `InlineSheet.jsx`에 `scrollIntoView` 없음을 검사. 당시 이유는 저장/취소 버튼이 sticky로 엉뚱한 위치에 뜨던 문제(그 해결 = 버튼을 문서 흐름에 둠)였고, 자동 스크롤 자체가 원인은 아니었음 → 보리 승인(2026-10-08)으로 이 결정을 바꿈.

### 목표 상태 (기대 동작)

1. **수정·추가를 눌러 칸이 열리면**: 펼쳐짐(0.4초)이 끝난 뒤 화면이 **부드럽게 내려가 입력 칸 맨 위(제목 "○일 일지 세부 입력 수정" 등)가 화면 위쪽에** 보임. 이미 칸이 화면 안에 다 보이면 거의 안 움직임.
2. **이미 열린 칸에서 다른 항목을 고르면**: 그 칸으로 다시 내려가고, 내용이 **서서히 다시 나타나** 바뀐 걸 알 수 있음(운행 일지·정비·주유·기타 모두).
3. 닫을 때는 스크롤을 건드리지 않음(지금처럼 접힘).
4. "동작 줄이기" 설정이면 부드럽게 대신 바로 이동, 서서히 나타남은 짧게(18-A와 같은 기준).
5. 저장/취소 버튼 위치·저장 동작은 그대로(sot 4-9의 "버튼은 문서 흐름" 유지).
