## 발견된 차이

### 1. 홈(메인 캘린더) — `mainPage` ↔ `/app`

- **테마 기본값 다름 — 버그 아님(확인됨)**: 원본은 `theme`을 localStorage에만 저장하고
  Supabase엔 안 올림(`script.js:2333` 주석 — "다크/라이트 모드는 예전엔 이 로컬 'theme'
  키에만 저장돼서 Supabase에 전혀 올라가지..."). 두 앱이 다른 포트(오리진)라 localStorage가
  완전히 분리돼 있어 테마가 다르게 보이는 건 설계상 정상. 실제 화면 차이 아님.
- **9월 6일 칩 누락 [실제 차이, 원인 특정됨]**: 원본 캘린더 6일 칸엔 "2만" 칩이 있는데
  react-app은 없음. `정비/주유/기타` 화면(§6)에서 대조해보니 **데이터 자체는 react-app에
  정확히 존재함** — 2026-09-06 정비 20,000원(엔진/카드/엔진·미션) 항목이 두 앱 다
  똑같이 조회됨. 즉 조회 자체는 정상이고, **홈 캘린더의 날짜 칩 렌더링(정비 등 지출을
  칩으로 합산해 표시하는 로직)만 이 항목을 놓치는 것으로 범위가 좁혀짐** — STATUS.md
  "알려진 이슈"에 있는 서브차량 지출 칩 관련 이슈들과 인접 영역이라 그쪽 코드부터
  살펴보면 빠를 것.
- **"월간 운송료 정산" 섹션 — 구조 자체가 다름 [실제 차이, 확인됨]**:
  - 원본: **거래처별**로 나눔 — "총 9회 운행" / "미지정 거래처 운송료 400,000원" /
    "고성노선(지우지말것) 기본 운송료 350,000원" / 부가세 75,000원 / 합계 825,000원
    **+ 차량 정비비 420,000원 + 차량 주유비 400,000원 + 통행료/기타 50,000원** (지출 3종
    별도 표시).
  - react-app: **입력 방식별**로 나눔 — "횟수 7회 · 세부 입력 2건" / "기본 운송료
    (횟수×단가) 350,000원" / "세부 입력 운임 400,000원" / 공급가액 750,000원 / 부가세
    75,000원 / 합계 825,000원. **차량 정비비·주유비·통행료 항목이 아예 없음.**
  - 합계(825,000원)는 우연히 일치하지만 집계 기준(거래처별 vs 입력방식별)이 서로 다르고,
    react-app엔 지출(정비/주유/통행료) 요약이 이 카드에서 통째로 빠져 있음. 원본에 있던
    정보가 react-app에서 안 보이는 케이스 — 이관 누락 후보.
- **"테스트님 · 달력에 횟수 기록" 문구 모순 [확인 필요]**: react-app 홈 하단에 이 문구가
  뜨는데, 실제 캘린더 칩은 금액("35만" 등)으로 표시되고 있어 "횟수 기록"이라는 문구와
  실제 표시가 어긋남. 원본엔 이 문구 자체가 없음(원본은 앱설정 안에 "달력 일일 표시 방식:
  횟수/금액" 토글이 있고 이 계정은 "금액"으로 설정돼 있음 — 스크린샷 확인). react-app이
  같은 설정값을 다르게 해석/표시하는 것으로 의심 — 설정 화면 대조 때 원인 추적 예정.

- **테마 저장 방식 자체가 다름 [아키텍처 차이, 확인됨]**: react-app은 `AppSettingsPage.jsx:120-131`에서
  테마를 `useOwnerSettings`(클라우드 동기화되는 `FinanceSettings.theme`)로 관리 —
  기기를 바꿔도 같은 계정이면 테마가 따라옴. 원본은 `localStorage.getItem('theme')`만
  써서 기기별로 따로 논다(§1 코드 인용 참고). 어느 쪽이 맞다 틀리다의 문제가 아니라
  **저장 위치 자체가 달라진 설계 변경**이라 보리 인지 필요.

  — **버그 아님**: "회사 정산" 라벨은 매출제/월급제 전환(Step 9) 이전 옛 개념이라
  react-app에서 이미 의도적으로 대체됐음(메모리 `react-app-driver-settlement-mode-taxonomy`
  참고). react-app이 전화번호를 추가로 보여주는 것도 누락이 아니라 추가 정보.

### 6-1. 거래처 — `clientManagementPage` ↔ `/app/clients`

- **react-app에만 있는 거래처 "연습운수" [중요, 우선 확인 필요]**: 원본 거래처 목록엔
  "고성노선(지우지말것)"·"주식회사 제일특수" 2건만 있는데, react-app은 그 사이에
  **"연습운수"(사업자 -, 연락처 -)가 하나 더 있음(총 3건)**. 같은 계정인데 원본이
  이 거래처를 아예 조회 못 하는 것으로 보임.

### 6-2. 미수금/정산 관리 — `receivablesManagementPage` ↔ `/app/receivables`

- **원본 "미수금 내역이 없습니다" ↔ react-app엔 미수금 2건 [중요, 우선 확인 필요,
  §6-1·§4와 연결 의심]**: react-app엔 "연습운수 2026년8월 운행분 메인차량 미수금
  100,000원 1건"·"미지정 거래처 2026년9월 운행분 2222 미수금 200,000원 1건" 2건이
  뜨는데, 원본은 이 화면에서 미수금이 하나도 없다고 나옴. 첫 번째 건이 위 §6-1
  "연습운수"와 같은 거래처라 **한 뿌리**로 보이고, 두 번째 건의 "2222"는 기사차량
  "22나2222"(운행일지, 미연동)를 가리키는 것으로 추정 — §4(매출 탭)의 "미입금
  운송료(1건) 200,000원"과 금액이 정확히 일치해 **같은 항목**으로 보임.
  → **잠정 결론(코드 확인 전, 가설)**: 서브차량(특히 22나2222처럼 기사 미연동인
  차량)이 만든 운행/거래처 데이터를 react-app은 정상적으로 조회·집계하는데, **원본이
  이런 서브차량 관련 데이터를 거래처·미수금·매출 화면 여러 곳에서 일관되게 못 읽고
  있는 것으로 의심됨.** 반대로 "어느 쪽이 정답 집계인지"는 이 조사만으로 단정 못 함 —
  코드 수정 없이 발견만 기록(§0 지시).

### 9. 운송비 내역서 — `reportPage` ↔ `/app/report`

  추정]**:
  - 원본: **날짜별 표**(9월1일 7회 350,000원 / 9월2일 1회 200,000원 / 9월4일 1회
    200,000원) + 거래처별 요약("고성노선(지우지말것) 기본 운송료 350,000원" 등) + 계

  - react-app: 날짜별 표 없이 "횟수 7회·세부입력 2건 / 1회 단가 50,000원 / 기본운송료

    400,000·통행료기타 50,000 항목이 추가로 있음**(원본엔 없던 지출 정보가 운송비

  구분 안 됨** — 화면 패턴 자체가 다르므로 직접 비교가 어려움, 필요하면 별도로
