# docs/report.md — 현재 슬라이스 착수지시서

## 4-2 산재보험·원천징수 재설계 — 슬라이스 3 "콜 상세 산재보험료 칸 정리" `[x]` 착수지시서 (react-app `e8cdc45`, 2026-09-27 최종 승인)

### 1. 목적 (비개발자용)
콜 상세(운행 건별)에 입력하는 "산재보험료" 칸은 원래 1인 차주가 본인 기록용으로 남기려던 것이다. 그런데 이 값이 **회사정산(company) 모드 기사차량의
매입 세금계산서 금액**(운송료−수수료−이 값)에는 아직도 실제로 쓰이고 있다는 걸 이번 조사에서 확인했다(보리 확인: 2번 — 그대로 둔다).
**기사연동 계정(고용된 기사 본인이 로그인한 세션)**은 자기 명의로 플랫폼 일을 받는 게 아니라 차주 소속으로 일하므로, 이 칸이 애초에 그 사람에게는
의미가 없다. 이번 슬라이스는 **그 칸을 기사연동 계정 화면에서만 숨긴다.** 계산 로직·세금계산서는 전혀 안 건드린다.

### 2. 이번 조사에서 확인한 사실 (보리 결정 2026-09-27)
- **매입 세금계산서**(`financeTaxInvoiceGroups.js:99-102`, `driverInvoiceBasis: 'net'`)가 콜 상세 건별 산재보험료 합(`totals.insuranceAmount`)을 여전히
  공급가액 계산에서 뺀다. **`[확인: 2026-09-27 보리 — 2번, 그대로 둔다]`** — 계산은 안 바꾸고, "1인 차주 본인 기록용"이라는 설명만 "회사정산 기사의
  매입계산서 공제 항목이기도 하다"로 정정한다(로드맵 문서만 수정, 코드 아님).
- (참고, 이번 슬라이스와 무관) 기사 관리 정산 요약 카드가 슬라이스 1에서 새 계산으로 바뀌면서, `getLinkedDriverSettlementDetail`이 돌려주는
  `insuranceAmount`·`finalAmount` 필드는 이제 화면 어디서도 안 읽는다. 지우지 않는다(그 함수는 매입 세금계산서 흐름과 얽혀 있어 범위 밖 — 건드리면
  §8-6에 걸리는 별도 조사가 필요, 이번엔 손 안 댐).

### 3. 확인한 배선 경로
`MainPageRoute.jsx`(이미 `session` prop 있음) → `DayLogPage.jsx`(콜 상세 조립) → `CallDetailForm.jsx`(입력칸 227줄, §6 예외 파일).
`CarListPage.jsx`가 이미 쓰는 것과 같은 패턴(`session?.accountType === 'employed_driver'`)을 그대로 재사용한다 — 새 판별 로직 안 만든다.

### 5. 안 건드릴 것 (근거 병기)
- `financeTaxInvoiceGroups.js`(매입 세금계산서 계산) — §2에서 보리가 "그대로 둔다"로 확정.
- `CallDetailList.jsx`의 "산재보험료" 합계 줄 — 코드 확인: `totalInsuranceFee > 0`일 때만 표시(32·62행). 기사연동 계정이 입력칸이 없어 새로 값을 못 만드니
  자동으로 0원이라 안 보인다. 과거에 이미 입력된 값이 있는 콜 상세는 계속 보여야 한다(값 삭제 금지 원칙) — 그래서 이 파일은 무수정.
- 콜 상세 저장 로직(`domain/call-details.js`) — 입력칸만 숨기는 것이라 저장 스키마·검증 로직 무변경. 저장 시 `insuranceFee`를 강제로 지우는 코드를
  넣지 않는다(기존 값 보존).
- "결제 및 수금 입력" 스위치가 꺼진 1인 차주는 이 슬라이스 뒤에도 여전히 이 칸을 못 본다(원래 구조 그대로) — **미확인, 이번 범위 아님**, 필요하면
  나중에 별도로 제기.

### 7. 검증
- `npm test`(unit+화면)·`npm run typecheck` 0에러·strict-inventory 진단 불증가(기준선 428).
- 신규 화면 테스트로: ① 기사연동 계정(`isEmployedDriver: true`)이면 `#callInsuranceFee` 칸이 안 보임(결제 스위치 켜진 상태에서도) ② 미연동/차주는
  결제 스위치가 켜지면 그대로 보임(기존 동작 불변) ③ 이미 `insuranceFee` 값이 있는 콜 상세를 기사연동 계정이 열어도 그 값이 draft에 남아 저장 시
  그대로 다시 저장됨(칸만 숨고 값은 안 지워짐).
- **테스트 진실성**: `!isEmployedDriver` 조건을 빼면 새 테스트가 FAIL하는지 CLI 원문으로 확인 후 원복.
