### 조사 (2026-10-03, `npm run build` + 지도 파일 분석)

- **사이드메뉴 배너가 가장 큰 문제:** `SideMenu.jsx:134-135`가 메뉴를 열 때마다 라이트·다크 배너 **둘 다** `<img>`로 넣고 CSS로 하나만 숨김(`side-menu.css:48-50`).
  브라우저는 숨긴 그림도 내려받으므로 처음 메뉴를 열 때 **약 3MB**(`banner_image_Light.png` 2.26MB + `banner_image_dark.png` 0.72MB)를 받음.
  원본은 1536×1024인데 화면엔 **높이 56px**(약 84×56)로만 보임 → 3배 고해상도 화면 기준으로도 252×168이면 충분.
- `banner_image.png`(144KB, 408×231)는 첫 화면·달력·첫 설정에서 높이 30~54px로 보임 — 줄일 여지는 있으나 작음.
- **메인 코드 파일 702KB(gzip 209KB):** 내용 대부분이 라이브러리(react-dom·Supabase·react-router)이고 화면 20개는 이미 따로 나뉘어 있음(`lazyPages.js`). 엑셀·PDF 라이브러리(각 0.9MB)는 이미 쓸 때만 받음.
  라이브러리를 별도 파일로 떼면(`manualChunks`) **첫 방문 속도는 거의 같고**, 앱을 고쳐 다시 배포할 때 라이브러리를 다시 안 받는 이점만 있음.
- **검증·배포가 따로 돎:** `ci.yml`(테스트·타입·빌드)과 `pages.yml`(빌드·배포)이 각자 설치·빌드 → **CI가 빨강이어도 배포 페이지에 올라감**(로드맵 옛 3번에 이미 기록).
- GitHub Pages는 gzip을 자동 적용(Brotli는 Pages에서 설정 불가) — 따로 할 일 없음.
