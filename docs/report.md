### 현재 상태

- 다운로드 파일에 점검표가 이미 들어 있음: `dailyInspections` → 차량 칸(`main`·서브 번호) → 날짜 → `{ items, actionNote, inspectorName }`(`memberBackup.js`).
- 불러오기(22-A·B·D, `memberRestore.js` 158줄)는 이 칸을 무시함.
- 점검표는 일지와 달리 **화면 기록(Store)에 없고 서버에만** 있음 — 일지를 열 때·서류 발급 때 서버에서 읽음(`dailyInspections.js`).
- 저장 `saveDailyInspection`은 "차량+날짜 1장 **덮어쓰기**"(서버 `upsert`) → 이미 있는 날에 부르면 기존 점검표가 바뀜. 그래서 저장 전에 서버에 있는 날짜를 꼭 먼저 읽어야 함.
- 서버 읽기 `fetchVehiclesDailyInspections(차량 id들)` — 다운로드가 쓰는 것, 한 번에 내 차량 전부.

### 목표 상태 (이번 슬라이스)

1. 파일을 고르면(확인 창 뜨기 전) 내 차량 점검표를 서버에서 한 번 읽어 **서버에 없는 날짜만** 고름. 읽기 실패면 "점검표를 확인하지 못했습니다. 잠시 후 다시 시도해 주세요." 안내하고 확인 창 안 띄움.
2. 차량 규칙은 22번과 같음: `main` → 내 메인 차량, 서브 번호 → 번호 같은 내 차량, 서버에 없는·연동 기사 붙은 차량은 건너뜀(`isOwnUnlinkedCar`).
3. 확인 창·결과 안내에 "점검표 N장" 추가(0이면 생략).
4. 저장 순서 맨 끝: 거래처 → 일지 → 지출 → 계산서 → **점검표**. 날짜마다 `saveDailyInspection`, 실패하면 멈추고 "먼저 저장됨" 안내(22-B와 같음).
5. 점검자 이름·조치 기록은 **파일 그대로** 넣음(그날 점검한 사람 기록이라 지금 이름으로 바꾸지 않음). 점검 항목 값은 기존 정리 규칙(`sanitizeInspectionItems` — good/bad만)으로 거름.
6. 모양이 틀리면(차량 칸·날짜·이름이 글자 아님 등) 파일 전체 "올바르지 않음"(22-A·B와 같음).
7. **연동 기사 계정(22-D)은 점검표를 건너뜀** — 22-D처럼 일지만. (기사 계정으로도 배정 차량 점검표를 넣어야 하면 말씀해 주세요.)
