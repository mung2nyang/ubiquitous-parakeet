### 재현 결과 (2026-10-09, 앱 코드를 그대로 불러 쓰는 임시 스크립트 — 실행 후 삭제)

1. 비회원(`guest`)에 메인 차량 12가3456·기사 차량 34나5678·거래처 1개를 넣고
2. 메인 차량 주유 지출 저장 → 휴대폰 저장소의 지출 목록 읽기 **정상(value)**
3. **기사 차량 정비 지출 저장 → 지출 목록 읽기 `schema`(형식 오류)**. 저장된 항목: `{"kind":"maint","vehicleNumber":"34나5678"}`
4. 앱을 다시 켠 것처럼 저장소에서 다시 불러오기(`initializeOwnerFromPersist('guest')`) → **차량 0 / 거래처 0 / 지출 0 / 일지 0** — 지출뿐 아니라 **전부 안 불러와짐**
5. 그 상태(화면엔 거래처 0개)에서 거래처를 하나 새로 등록 → 저장소 거래처 **1개 → `["새거래처"]`** — **기존 거래처가 지워짐**
6. 같은 상태에서 백업 파일을 만들면 **지출이 통째로 빠짐**(차량은 들어감)

### 원인 (코드 확인)

- 기사 차량 지출에는 2026-09-07(`987be18`)부터 차량 번호 칸 `vehicleNumber`가 붙음(`domain/expenses.js:76·120`).
- 그런데 휴대폰 저장소 형식 검사의 지출 허용 칸 목록(`store/persistDomainRecords.js:51` `EXPENSE_KEYS`)에 `vehicleNumber`가 **빠져 있음** → 기사 차량 지출이 하나라도 있으면 지출 목록 전체가 "형식 오류".
- 다시 켤 때 불러오는 코드(`store/owner-state.js:56-57`)는 **한 종류라도 형식 오류면 아무것도 안 불러오고 멈춤**(망가진 자료로 덮어쓰지 않으려는 안전장치, 플레이북 §1). 그래서 화면이 비고,
- 빈 화면에서 새로 입력하면 그 종류 목록을 통째로 다시 저장 → 저장소에 남아 있던 기존 기록이 덮여 지워짐.
- **로그인 회원은 해당 없음** — 회원의 업무 기록은 휴대폰 저장소에 안 쓰고 서버에만 둠(`store/batchWrites.js:29` `CLOUD_MEMORY_ONLY_DOMAINS`에 expenses 포함).
- 비회원 + 기사 차량 + 그 차량 지출 입력, 세 가지가 모두 있어야 생김. 실사용자 없음(지금까지 실제 피해 없음).

### 목표 상태 (기대 동작)

1. 비회원이 기사 차량 지출을 넣어도 지출 목록 형식 검사가 통과 → 다시 켜도 차량·거래처·지출·일지가 모두 그대로 불러와짐.
2. `vehicleNumber`는 **글자일 때만** 허용(다른 칸과 같은 방식으로 종류 검사) — 엉뚱한 값은 지금처럼 형식 오류.
3. 이미 이 상태에 빠진 휴대폰(저장소에 기록은 남아 있고 불러오기만 막힌 경우)은 고친 앱을 다시 켜면 자동으로 다시 불러와짐(저장소 기록은 그대로라서). 이미 덮어써진 기록은 되살릴 수 없음.
4. 백업 파일에도 기사 차량 지출이 들어감.
