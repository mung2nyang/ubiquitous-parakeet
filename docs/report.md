### 1. 목적 (쉬운 말)
일상점검표 사용이 켜진 차량의 일일운행 일지에 **안내 줄**을 넣고, 누르면 **점검표 모달**(입력·보기 한 창)이 뜬다. 저장하면 서버(9-A 표)에 바로 기록.
확정 규칙: 로드맵 9번 ①③④⑤⑥⑪·"9-B 정한 것". 모양은 피그마 1(일지)·2(입력)·3(보기)과 최대한 같게.

### 2. 조사 (근거)
- 일지 화면 `DayLogPage.jsx` 227줄(229까지 승인됨). 고정 노선 카드(`DayLogPage.jsx:156-165`, 고정 노선 꺼짐이면 없음) 다음, 콜 목록 앞이 피그마 위치.
  이 화면의 설정(`settings`)은 이미 차량별로 합쳐져 있음(`resolveLogSettings` — 기사차량이면 그 차량 설정, 9-B-1에서 `dailyInspectionOn` 포함). 휴무 = `draft.isOff`.

### 3. 하는 일
1. `domain/dailyInspectionItems.js`(신규): 법정 서식 순서·문구 그대로 3묶음 11항목(01 외관 점검 4 · 02 상태 점검 3 · 03 기타 4)과 영어 항목키, 결과 good/bad 이름표("양호"/"불량").
2. `lib/dailyInspections.js`(신규): 그 차량·날짜 점검표 1장 읽기, 저장(차량+날짜 덮어쓰기, 작성자 = 로그인 사용자, 점검자 이름 = 저장 순간 이름). 서버 값 형식 검사 후 사용.
3. `components/day-log/DailyInspectionNotice.jsx`(신규): 안내 카드 — 켜짐·휴무 아님·로그인·차량이 서버에 있음일 때만. 열 때 서버에서 1장 읽음.
   없으면 "일상점검표 작성이 필요합니다. [+ 입력]", 있으면 "○월 ○일 일상점검표 작성이 완료 되었습니다. [보기]". 읽기 실패면 "일상점검표를 불러오지 못했습니다. [다시 시도]"(확인 3).
4. `components/day-log/DailyInspectionModal.jsx`(신규): 입력·보기 한 창. 머리 = 왼쪽 <(닫기)·가운데 "○월 ○일 일상점검표"(파란 글씨)·보기 모드 오른쪽 연필(→ 같은 창 입력 모드).
   입력 모드: 섹션 머리(번호 배지+제목, 첫 섹션 머리 오른쪽 [모두 양호])·항목마다 [양호][불량](고른 쪽 강조)·서명 문구 "본인은 위 점검 내용을 사실대로 확인하였습니다. / 점검자: 이름 (자동 서명)"·
   "불량상태 조치 기록" 입력칸(예시 "(예시)창닦이기 불량", 비워도 됨)·[취소][저장]. 보기 모드: 항목마다 양호/불량 배지, 조치 기록 글 상자.
   바깥 클릭: 입력 모드 안 닫힘(8번 규칙), 보기 모드 닫힘. 저장 성공 → 창 닫고 안내 줄이 "완료"로, 실패 → 토스트·입력 그대로.
5. `components/day-log/daily-inspection.css`(신규): 위 모양(새 클래스만, 기존 `.modal-overlay` 재사용).
6. `DayLogPage.jsx`: 불러오기 1줄 + 고정 노선 카드 다음에 안내 카드 1줄(229줄, 승인 범위).

### 6. §8 5대 질문
1. 점검표 = 화면이 열릴 때 서버에서 읽음(구독 아님), 설정·휴무 = 기존 구독값. 2. 값 = 서버 `daily_inspections` 1장(로컬 보관 없음). 3. 쓰기 = 새 `lib/dailyInspections.js` 저장 1곳.
4. 같은 차량·날짜는 1장(서버 유일) — 저장은 덮어쓰기. 다른 기기에서 고친 값은 일지를 다시 열 때 반영. 5. 권한 = 9-A 서버 규칙(운행자만 작성).
플레이북 트리거(`lib/*` 저장) — 착수 전 `testing-playbook.md` §1·§6.

### 7. 기대 동작
- 스위치 켠 차량의 일지(휴무 아님)에 안내 줄. 꺼진 차량·휴무 날·비회원은 없음. 휴무를 풀면 다시 보임(저장분 그대로).
- [+ 입력] → 입력 모달 → 저장 → 안내 줄 "완료" → [보기] → 읽기 전용(항목 배지·조치 기록·점검자) → 연필 → 저장값 채운 입력 → 고쳐 저장.
- 새로고침·다른 날짜 이동 후 다시 와도 그날 점검표 그대로. 연동 기사도 배정 차량 일지에서 똑같이.

### 8. 실패 시 처리

### 10. 확인 요청
1. **저장 조건** — 추천: **11항목을 모두 골라야 저장**(빈 항목이 있으면 "모든 항목을 선택해 주세요" 안내). 법정 기록이라 미리 "양호"로 채워 두면 확인 없이 저장될 위험.
   다른 방법: 처음부터 모두 양호로 채워 두고 불량만 바꾸기(빠름).
2. **수정 중 [취소]** — 추천: 보기에서 연필로 들어온 경우 **보기 모드로 돌아감**(바꾼 것 버림), 처음 입력 중 [취소]는 창 닫기.
3. **읽기 실패 표시** — 추천: 안내 줄 자리에 "일상점검표를 불러오지 못했습니다. [다시 시도]".
