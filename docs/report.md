## 1. 착수 전 코드 확인 (감시관, 2026-09-07)

관련 파일 3개를 직접 읽어봤다 — `domain/calendarBadges.js`
(`dayExpenseBadgeLabel`), `components/calendar/CalendarGrid.jsx`,
`components/calendar/CalendarPage.jsx`. 로직 자체는 지금 봐도 맞아 보인다:

- `CalendarPage.jsx`가 `expenses = useOwnerExpenses(ownerKey)`를 읽어
  `CalendarGrid`에 `expenseVehicle={isMain ? undefined : logId}`로 넘김
  (메인 캘린더는 `undefined` — "차량 태그 없는" 지출만).
- `CalendarGrid.jsx`가 각 셀마다 `dayExpenseBadgeLabel(expenses, cell.key,
  expenseVehicle)` 호출.
- `dayExpenseBadgeLabel`이 `filterByDate`로 날짜 매칭 + `vehicleNumber`
  트림 비교로 태그 매칭 + `cost` 합산 — 눈으로 보기엔 결함 없음.

**중요한 시간 순서**: 이 버그를 처음 발견한 "원본↔React UI 전수 대조 1차
조사"는, 서브 차량 지출 칩 관련 슬라이스(`987be18` "서브 차량 지출 칩
이관 1단계", `f45d198` "서브 일지 지출 목록 차량 필터 재오픈 수정")**보다
나중에** 진행됐다(STATUS.md "완료" 목록 순서로 확인). 즉 그 두 슬라이스가
이미 반영된 상태에서도 9/6 칩이 여전히 안 보였다는 뜻 — 코드만 다시
읽어서는 새로 눈에 띄는 결함이 없다.

**결론**: 코드 정적 분석만으로는 원인을 못 찾겠다. 실제 데이터로 재현해야
한다 — 감시관은 로그인 테스트 계정이 없어 직접 재현 불가.
